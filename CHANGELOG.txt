v1.4 — 2026-10-28 晚 · 远程调试能力
================================================================================

【新增】服务端 server2.py
--------------------------------------------------------------------------------
- POST /api/upload_log
    接收 gzip 压缩日志，按 device_id_yyyyMMdd_HHmmss.log 命名存 uploads/logs/
    （替代 ADB 拉日志，手机不在身边也能拿日志）
- GET /api/logs
    返回日志列表（文件名 / 大小 / mtime），供 Web 面板展示
- GET /api/download_log?name=xxx
    下载日志，os.path.basename 过滤防路径穿越
- /api/control 新增 5 个 action：
    upload_log / locate_once / scan_wifi / restart_udp / test_low_battery
- Web 面板「高级设置」新增 6 个按钮：
    📤 拉取日志(主服务器) / 📋 查看手机日志 / 📍 手动定位一次
    📡 手动扫描 WiFi / 🔄 重启 UDP 监听 / 🧪 模拟低电量
- 启动时打印日志上传目录的绝对路径

【新增】客户端 TrackingService.java
--------------------------------------------------------------------------------
- ACTION_UPLOAD_LOG
    读 device_log.txt → gzip 压缩 → POST /api/upload_log
    支持 temp_url（临时服务器）和 clear_after（上传后清空本地）
- ACTION_UPDATE_RUNTIME_CONFIG
    运行时改 report_interval_seconds / accuracy_mode /
    enable_motion_trigger / enable_wifi_lock
    不用改服务端 GLOBAL_DEFAULT_CONFIG 再等上报
- ACTION_LOCATE_ONCE
    手动触发一次定位+上报，调试定位不用等定时/SENSOR
- ACTION_SCAN_WIFI
    手动扫描 WiFi，逐条记录 SSID + RSSI
- ACTION_RESTART_UDP
    手动重启 UDP 监听，不用等 5 秒自动重连
- ACTION_TEST_LOW_BATTERY
    模拟 15% 低电量告警，不用真等电量掉到 15%
- 5 个对应 UDP 指令：
    FIND_ME_UPLOAD_LOG / FIND_ME_LOCATE_ONCE / FIND_ME_SCAN_WIFI /
    FIND_ME_RESTART_UDP / FIND_ME_TEST_LOW_BATTERY
- uploadLog() 方法
    gzip 压缩 + FixedLengthStreamingMode + 上传后可选清空
- import 新增：ByteArrayOutputStream / GZIPOutputStream / FileInputStream

【新增】工具
--------------------------------------------------------------------------------
- rescue.py 选项 14-20
    14 拉日志（主服务器）/ 15 拉日志（临时服务器）/ 16 改上报间隔

v1.2 — 2026-10-28 中午 · 502 根因修复
================================================================================

【修复】server2.py · 502 根因
--------------------------------------------------------------------------------
- 问题：旧代码 recv(16384) 只读一次，TCP 分段时 body 不完整
        → json.loads 失败 → except 只 print 不回响应
        → Cloudflare 判 502
- 修复：
    1. 按 Content-Length 循环 recv(65536) 读完整 body
    2. 所有 except 分支补 sendall(500) + Connection: close
    3. 所有响应加 Connection: close
    4. 分支判断改用 header_text（避免 body 里的路径字符串误判）
- 验证：
    · 本地非法 JSON → HTTP 500（不再是 curl: (52) Empty reply）
    · 本地合法大 JSON（12.5KB / 200 个热点）→ HTTP 200
    · 公网域名非法 JSON → HTTP 500
    · 12:21 部署后，两台设备零 502

【修复】server2.py · KeyError
--------------------------------------------------------------------------------
- 问题：新设备首次上报带 cloud_logs 时
        ALL_DEVICES_STATUS[dev_id] 不存在 → KeyError
- 修复：先 if dev_id not in ALL_DEVICES_STATUS: ALL_DEVICES_STATUS[dev_id] = {}
        再合并 cloud_logs

【变更】server2.py
--------------------------------------------------------------------------------
- init_db() 加 timeout=10 + PRAGMA journal_mode=WAL（防并发写丢数据）
- 所有 sqlite3.connect() 加 timeout=10
- udp_listener 的 except OSError 判断 errno 98/10048，
  明确提示 8888 被 chat.py 占用
- allDevicesData = json.dumps(...).replace('</', '<\\/')
  （防 WiFi SSID 含 </script> 破坏页面）
- smart_send 用 list(ALL_DEVICES_STATUS.items()) 快照（防并发 RuntimeError）
- format_loc_time 的 except: 收窄为 except Exception:

已知问题 / 待办
================================================================================

【未解决】
--------------------------------------------------------------------------------
- 中兴 A2023BH force-stop
    原因：Android 11 + 安全补丁 2022-10-01，旧版 MyOS 省电策略激进
          stopped=true 后静态广播失效，
          START_STICKY / BOOT_COMPLETED / SECRET_CODE 全部无效
    结论：代码层无解，只能 ADB 或用户手动打开 App
- 红米 Note 8 电量卡 1% 7 小时
    原因：电池老化/校准异常，非 App 问题，建议校准或换电池
- MainActivity.hideLauncherIcon() 与 handleIconVisibility() 冲突
    MainActivity 会禁用 alias，但 TrackingService 启动又启用，实际图标常驻
    若想隐蔽性更高，应改回 disable（但会失去 force-stop 后点图标自救的能力）

【建议但未做】
--------------------------------------------------------------------------------
- 位置节流（静止时 SENSOR 触发跳过）
    当前日志显示位置一直在变，收益可能不如预期
- 1% 时只发一次低电量告警（现在每 6 小时一次）
- 厂商推送通道（小米/华为）
    用户明确不引入第三方
- MainActivity 引导国产 ROM 的「自启动 / 后台运行 / 电池优化」三件套
- 铃声状态检测（静音/勿扰）
    只有「警报可能响不了」一个场景有直接价值，优先级低

【已验证】
--------------------------------------------------------------------------------
- 服务端 502 修复：12:21 部署后两台设备零 502
- SENSOR 节流 15min：两台设备实测间隔 ≥15 分钟
- 离线跳过：红米 16:17 飞行模式下正确跳过
- 6 小时心跳：偏差 7-23ms（Android 15）/ 几百 ms（Android 11）
