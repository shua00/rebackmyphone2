【0】前置：连接手机
--------------------------------------------------------------------------------
adb connect 192.168.1.xxx:PORT     # 无线调试（端口见手机设置）
adb devices                        # 确认设备在线

用 -s 指定设备（多设备时）：
adb -s 192.168.1.xxx:PORT shell ...


【1】生命周期控制
--------------------------------------------------------------------------------
# 启动 App 主界面
adb shell am start -n com.example.devicefinder/.MainActivity

# 模拟 force-stop（危险，验证自救能力用）
adb shell am force-stop com.example.devicefinder

# 手动拉起服务
adb shell am startservice -n com.example.devicefinder/.TrackingService

# 查看进程是否存活
adb shell ps -A | findstr devicefinder

# 查看服务状态
adb shell dumpsys activity services com.example.devicefinder | findstr "ServiceRecord"

# 查看是否被 force-stop
adb shell dumpsys package com.example.devicefinder | findstr stopped=

# 查看电池优化白名单
adb shell dumpsys deviceidle whitelist | findstr devicefinder


【2】ACTION 调试指令（startservice + action）
--------------------------------------------------------------------------------
# 强制上报一次
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_FORCE_REPORT

# 改主服务器 URL
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_UPDATE_SERVER --es server_url http://192.168.1.123:8080/api/report

# 改配置中心 URL
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_UPDATE_CONFIG_URL --es config_url https://example.com/config.txt

# 播放警报 30 秒
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_PLAY_ALARM

# 弹悬浮消息
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_SHOW_MSG --es message "测试消息"

# 弹留言板
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_SHOW_HISTORY

# 清空留言
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_CLEAR_HISTORY

# 锁 / 解锁聊天
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_LOCK_CHAT
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_UNLOCK_CHAT

# 手动触发保活心跳
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_KEEP_ALIVE

# 模拟定时上报
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_ALARM_TRIGGER

# 模拟 6 小时心跳
adb shell am startservice -n com.example.devicefinder/.TrackingService -a ACTION_HEARTBEAT

【5】日志查看
--------------------------------------------------------------------------------
# 查看完整日志文件
adb shell cat /sdcard/Android/data/com.example.devicefinder/files/device_log.txt

# 只看最后 50 行（持续观察）
adb shell "tail -f /sdcard/Android/data/com.example.devicefinder/files/device_log.txt"

# logcat 分类过滤（按 TAG）
adb logcat -s DF_SERVICE DF_REPORT DF_UDP DF_SMS DF_ALARM DF_LOCATION DF_WIFI DF_BATTERY DF_MEMORY DF_STORAGE DF_TRAFFIC DF_NETWORK DF_CHAT DF_CONFIG DF_UPLOAD_LOG DF_BOOT DF_POWER

# logcat 关键事件
adb logcat -d | findstr /i "devicefinder FATAL ANR BackgroundActivityStart force-stop"

# 崩溃日志
adb logcat -d -b crash | findstr /i devicefinder

【常见问题速查】
================================================================================

Q: 拨号暗号（*#*#8866#*#*）没反应？
A: 检查手机是否被 force-stop（dumpsys package | findstr stopped=），
   如果 stopped=true，暗号不生效，必须先手动打开一次 App。

Q: 上报返回 502？
A: 服务端 server2.py 旧版本，except 不回响应，Cloudflare 判 502。
   部署修复版（按 Content-Length 读 + except 回 500）即可。

Q: force-stop 后怎么救？
A: 三种方式：
   1. ADB: adb shell am start -n com.example.devicefinder/.MainActivity
   2. 用户手动打开 App（图标或暗号）
   3. 厂商推送通道（未实现）
   代码层无法解决，是系统机制。

Q: SENSOR 触发太频繁？
A: 已经节流 15 分钟一次，如果仍然频繁，检查手机是否被频繁移动。
   可以用 ACTION_UPDATE_RUNTIME_CONFIG --es enable_motion_trigger false 临时关闭。

Q: 定位不准 / 无定位？
A: 1. am startservice -a ACTION_LOCATE_ONCE 手动触发
   2. dumpsys location | findstr devicefinder 看监听数
   3. 日志里找 LOCATION 关键字看 provider 状态
